## 修复：插件启动后「包含的组件」显示状态异常（FAILED）

- 现象：设置 → 插件 → 会话秘书 的「包含的组件」行状态异常。`~/.dsh/dsh-session-secretary/gateway.log`
  每次启动只有两行（`[interaction] 已接管 userQuestions` + `[boot] ChannelManager 构造`），
  既没有 `[boot] apply 完成` 也没有 API 注册记录 → apply 中途抛错，cordis fiber 落到 FAILED。
- 根因：`src/index.ts` 里 `bridge.setUserQuestions(ctx.userQuestions)` 用**属性读取**一个没进
  `inject` 的服务。cordis 4 对此直接抛 `cannot get property "userQuestions" without inject`；
  宿主是在自己的 fiber 里 provide 该服务，所以消费方属性读取必炸（`get('userQuestions', false)` 正常）。
- 修复：新增 `readUserQuestionsService(ctx)`，统一走 `ctx.get('userQuestions', false)` 非严格读；
  服务在场则注入代答桥，缺席走桥的降级路径。已提交（含 lib 产物）。
- 回归测试：`tests/plugin-boot.test.mjs` —— 必须用真实的 `ctx.plugin()` 挂载才能复现
  （直接调 `apply` 不会触发 fiber 语义，测不出这个错）；覆盖服务由宿主插件 provide、服务缺席两场景。

## 可复用经验（cordis 4 插件）

- 未列入 `inject` 的服务**只能**用 `ctx.get(name, false)` 读，属性读取会抛错并让整个插件 FAILED
  （同仓库 `src/engine/router.ts` 早有同类注释：`ctx.sessions`）。
- 排查「插件起不来」：`gateway.log` 看 boot 断点；用 `new Context()` + `ctx.provide(...)` +
  `ctx.plugin(...)` 搭最小宿主复现，比直接调 `apply` 更接近真实语义。
- 本机 `~/.dsh/profiles/desktop` 是宿主 profile，插件以 `link:` 指向本工作区，改完必须 `npm run build`
  （宿主加载的是 `lib/`）。
