## 目标与业务边界

修复原生侧栏点击「频道」导致整个工作区插槽崩溃的问题，保证 IM 与定时插件无论谁先启动，都能向当前侧栏接入各自页签，并在卸载、重新启用及外壳替换时正确清理和恢复。

只调整两仓库的侧栏渲染与接入协议，不修改宿主、插槽权限、插件身份、设置入口、会话业务或依赖版本，不操作日常 Web/Desktop 进程。

## 根因与方案

1. 定时外壳原先对 `channels` 无条件跳过贡献 renderer，已成功注册的频道也会落到 `renderSlot('sidebar.channels')`。工作区 entry 不拥有这个子槽位权限，宿主抛错后整个侧栏区域消失；不能将此直接归因于启动竞态。
2. 沿用现有 `__dshNativeTabs` v1 协议，不新增全局总线或外部依赖：先启动者提供外壳，后启动者只贡献页签。频道可用性与内容渲染以同一注册表为准，删除跨槽回退，不通过捕获异常后画空白来冒充可用。
3. 带 `component` 的 entry 只认当前显示组件上的注册表，不回退 entry 残留缓存；对象或函数直接携带注册表的发现方式保留。协作注册表必须声明 `version === 1` 并提供 `getTabs`、`subscribe`、`insert` 三个函数。
4. 当前外壳不再使用旧注册表时立即释放本插件的贡献。新注册表通过宿主插槽订阅或 `dsh-native-sidebar-change` 通知重新接入，已有有限启动重试只是兜底，不作为跨插件启动顺序正确性的前提。
5. 同名页签由注册令牌限定清理权限，旧清理函数不能删除后来替换的贡献；外壳只由所属插件在仍持有组件时恢复，不能覆盖其他插件后来的替换。

## 任务清单与验收标准

- [x] 已注册频道被点击后执行频道 renderer，不调用工作区的跨槽接口。
- [x] 频道贡献未就绪时不显示不可用入口；迟到注册后可点击，卸载后回到任务树。
- [x] 两仓库以当前组件定位注册表，拒绝不完整或不兼容的注册表。
- [x] 换壳且新表迟到时清理旧贡献，通知到达后重新接入，不误删其他注册者的页签。
- [x] 双向启动顺序、通知延迟、优先级外壳替换、Codex UI 切换和热卸载后重新启用的组合验证通过。
- [x] 两仓库构建及既有全量测试通过，产物包含修复。
